# 90 秒課堂展示腳本

> 本檔是針對目前主題「LINE × 本地 AI 記帳小幫手」的 **90 秒課堂展示講稿**。

## 課前 5 分鐘（一定要做）

1. 開啟 Ollama：

   ```powershell
   ollama serve
   ```

2. 雙擊 `start_demo.bat`，確認 `http://127.0.0.1:5001/demo` 打得開。

3. **先記一筆暖機**（不要給大家看）：在展示頁輸入 `咖啡 45 元`，等它回覆累計。

4. **重新整理頁面**：聊天室清空、支出清單清空（刪掉本機的 `expenses.txt`）。

5. 把瀏覽器縮放設為 100%，確認投影機看得到右側的流程面板。

6. 備援：把 `docs/screenshots/demo-answer.png` 開在另一個分頁。

> 為什麼要暖機：冷啟動要載入模型，可能 15～25 秒；暖機後記帳與回答都很快。90 秒很短，不要把時間花在等模型。

## 逐字稿（90 秒內可背，但不要念太快）

> 大家好，我是…。
> 今天這個專案叫「LINE × 本地 AI 記帳小幫手」。
> 一個聊天視窗，搞定記帳跟查資料。
> 問題是：記帳不想開 App、手動打分類；查資料不想切 App。
> 我想把兩個動作留在同一個視窗。
> 輸入「咖啡 45 元」，本地解析出 merchant 跟金額，分類飲食，回今日累計、本月累計、上個月累計。
> 訊息到 Apps Script → Flask；本地解析、分類、累計、回覆。這條路完全不用 API。
> 約 0.3 秒完成，沒有打 API。跨月比較也有。
> 同一個流程，分類變交通。Uber 60，累計自動加總。
> 整個架構是雲端收發、本機記帳與推論。電腦關掉，服務就會停，這是目前最大的限制。
> 我已經寫了 17 個測試，也做了不需要 token 的展示頁。
> 下一步是 AI 分類、Flex Message、Webhook 簽章驗證。謝謝。

## 如果現場出錯

| 狀況 | 處理 |
|---|---|
| 記帳回覆卡住 | 不會卡（本地）；若卡，切備援分頁。 |
| 模型沒回應（查資料時） | 切到 `demo-answer.png` 備援分頁。 |
| 瀏覽器打不開 | 確認 `start_demo.bat` 視窗、Ollama 在跑。 |
| 投影比例跑掉 | 縮小到 80%，只投影手機區。 |
| 有人問「這跟 ChatGPT 有什麼不同？」 | 差別：本機推論、免逐字費用、跨月比較、累計即時更新。 |

## 預期 Q&A

**Q：為什麼不直接用 ChatGPT？**
A：可以，但這個專案想解決「不想把每句話送到雲端模型」與「不想付逐字費用」，且練習完整工程流程。

**Q：記帳是不是很簡單？**
A：目前是本地規則解析；後續要改 AI 分類。

**Q：為什麼要用 Apps Script？**
A：LINE 需要公開 HTTPS 端點，免費、不用養伺服器。

**Q：為什麼 2B 模型？**
A：9B 在純 CPU 上太慢，會超 LINE 回覆時限；2B 明顯快很多。

**Q：token 安全嗎？**
A：不進 repo；本機環境變數、Apps Script 指令碼屬性；交件前掃描腳本檢查。

**Q：為什麼不全部放雲端？**
A：雲端要 API 費用與帳號；本機沒有公開 Webhook；折衷：雲端收發、本機推論。
