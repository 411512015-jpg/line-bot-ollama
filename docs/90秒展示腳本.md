# 90 秒課堂展示腳本

## 課前 5 分鐘（一定要做）

1. 開啟 Ollama：

   ```powershell
   ollama serve
   ```

2. 雙擊 `start_demo.bat`，確認 `http://127.0.0.1:5001/demo` 打得開。

3. **先記一筆暖機**（不要給大家看）：在展示頁輸入 `咖啡 45 元`，等它回覆累計。

4. **重新整理頁面**：聊天室清空、支出清單清空（刪掉本機的 `expenses.txt`）。

5. 把瀏覽器縮放設為 100%，確認投影機看得到右側的流程面板。

6. 備援：把 `docs/screenshots/demo-answer.png` 開在另一個分頁；如果現場網路或模型卡住，直接切過去。

> 為什麼要暖機：冷啟動要載入模型，可能 15～25 秒；暖機後記帳與回答都很快。90 秒很短，不要把時間花在等模型。

## 逐字稿（可背，但不要念太快）

> 這是一個放在 LINE 裡的 AI 記帳小幫手。
>
> 使用者說「咖啡 45 元」，它就自動分類、累計；想查資料就說「查 …」。
>
> 第一個模式是「記帳」。我輸入「咖啡 45 元」。本地就把 merchant（咖啡）跟金額（45 元）抽出來，分類成飲食，回今日累計與本月累計。
>
> 訊息先到 Apps Script，再轉到這台電腦的 Flask；本地解析、分類、累計，最後回覆。這條路完全不用 API。
>
> 幾秒內完成，沒有打 API。來源不是裝飾——這裡改講累計。
>
> 第二個模式：同一個流程，分類變成交通。Uber 60，累計自動加總。
>
> 整個架構是雲端收發、本機記帳與推論。Apps Script 只負責接 LINE，真正的解析和模型在我電腦；電腦關掉，服務就會停，這是目前最大的限制。
>
> 我已經寫了 17 個測試，也做了不需要 token 的展示頁。下一步是 AI 分類、Flex Message、Webhook 簽章驗證。謝謝。

## 如果現場出錯

| 狀況 | 處理 |
|---|---|
| 記帳回覆超過 20 秒 | 不會發生（本地），若發生就切備援分頁。 |
| 模型沒回應（查資料時） | 切到 `demo-answer.png` 備援分頁，說「這是剛剛同一題的實測畫面」。 |
| 瀏覽器打不開 | 確認 `start_demo.bat` 視窗還在、Ollama 有在跑；必要時重開，改用截圖。 |
| 投影比例跑掉 | 瀏覽器按 `Ctrl` + `-` 縮小到 80%，或只投影中間手機區。 |
| 有人問「這跟 ChatGPT 有什麼不同？」 | 差別是本機推論、免逐字費用、累計即時更新，而且記帳與查資料在同一個入口。 |

## 預期 Q&A

**Q：為什麼不直接用 ChatGPT？**
A：可以，但這個專案想解決的是「不想把每句話都送到雲端模型」與「不想付逐字費用」。另外，我想練習 Webhook、非同步、搜尋與 prompt 的整合，不只是接一個 API。

**Q：記帳是不是很簡單？**
A：目前是本地規則解析（「咖啡 45 元」→ merchant + amount），分類用關鍵字 heuristic；後續要改成 AI 分類或使用者自訂類別。

**Q：為什麼要用 Apps Script？**
A：LINE 需要公開 HTTPS 端點。Apps Script 免費、不用自己養伺服器，很適合當收發與轉接層；比較重的工作留給本機。

**Q：2B 模型答得準嗎？**
A：不完美。所以流程是「先搜尋、再生成、附來源」，讓使用者可以查證；如果找不到資料，prompt 也要求它直接說查不到。

**Q：token 安全嗎？**
A：token 不進 repo。本機用環境變數，Apps Script 用指令碼屬性；交件前還跑了一個掃描腳本檢查金鑰與部署網址。

**Q：為什麼不全部放雲端？**
A：全部放雲端更穩，但需要 API 費用與帳號；全部放本機則沒有公開 Webhook。這個專案選的是折衷：雲端收發、本機推論。
